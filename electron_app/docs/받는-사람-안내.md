# SparkOn Manager 받는 사람 안내

SparkOn Manager 는 호마다 액티비티를 양산하는 데스크톱 앱입니다. 켜면 창 제목에는 「스파크온 매니지먼트」로 보입니다.
영어, 수학, 국어, 누리 과목을 다룹니다.
이 안내를 위에서부터 차례로 따라 하면 처음 켜서 진행판이 열릴 때까지 갈 수 있습니다.

## 1. 미리 설치할 것

앱을 켜기 전에 아래 넷을 설치합니다. 앱의 「초기 설정」도 이것들이 있는지 다시 확인합니다.

| 프로그램 | 설치 | 확인 명령 |
|---|---|---|
| Git for Windows | https://git-scm.com/downloads/win 에서 받습니다. 설치할 때 **Git Credential Manager(자격 증명 관리자)** 를 같이 설치합니다. 기본값 그대로 두면 들어갑니다 | `git --version` |
| Node.js | https://nodejs.org/en/download 에서 **22.13 이상**의 22 LTS 를 받습니다. 20.19 이상의 20, 23.5 이상의 23, 24 이상도 됩니다 | `node -v` |
| yarn 1 | Node.js 를 설치한 뒤 **새 PowerShell 창**에서 `npm install -g yarn` 을 실행합니다. yarn 2 이상은 쓸 수 없습니다 | `yarn -v` (1 로 시작해야 합니다) |
| Claude Code | https://code.claude.com/docs/en/setup 을 따라 설치합니다. 설치한 뒤 PowerShell 에서 `claude` 를 실행해 **로그인까지** 합니다 | `claude --version` |

- git.example.com 계정이 있어야 합니다. `your-org/activity-forge` 저장소를 받을 수 있고, 맡은 호 저장소와 sparkon_common 에 올릴 수 있는 계정인지 담당자에게 확인합니다.
- Claude Code 에 로그인할 계정도 담당자에게 확인합니다.
- 설치가 끝나면 PowerShell 창을 새로 열어 확인 명령을 실행해 봅니다. 열어 둔 창에서는 새 프로그램이 안 잡힐 수 있습니다.
- PowerShell 에서 「스크립트를 실행할 수 없으므로」 같은 오류가 나면 명령 프롬프트(cmd)를 열어 같은 명령을 실행합니다.
- 기획서 PDF 를 읽는 poppler 는 실행 파일에 들어 있어 따로 설치하지 않습니다.

## 2. 실행 파일 받기

1. git.example.com 에 로그인합니다.
2. `your-org/activity-forge` 저장소의 「릴리스」에서 가장 새 릴리스를 엽니다.
3. 실행 파일 `SparkOn-Manager-<버전>.exe` 와 「실행이 막히면.txt」를 같이 받습니다.
4. 실행 파일은 설치 없이 바로 켜집니다. 알기 쉬운 곳에 둡니다.

서명하지 않은 실행 파일이라 Windows 가 실행을 막을 수 있습니다. 파란 창이 뜨거나 아무 창도 안 뜨면 「실행이 막히면.txt」를 따라 합니다.

## 3. 작업 폴더 정하기

작업 폴더는 호 저장소(`sparkon_mNN`)를 받아 둔 폴더입니다. **이미 받아 두었다면 그 폴더 경로만 고르면 됩니다.** 앱이 이 안에 폴더 둘을 더 만듭니다.

- 같은 폴더에 resource_common, sparkon_common, sparkon_cli 도 있어야 합니다. sparkon 명령으로 호를 받았다면 이미 있습니다.
- 네트워크 폴더는 쓸 수 없습니다.
- 처음부터 받는다면 짧은 경로의 폴더를 쓰고 OneDrive 아래는 피합니다. 남은 용량은 어림으로 30~40GB 를 잡습니다.

## 4. 처음 켜기 — 초기 설정

실행 파일을 켜면 「초기 설정」이 뜹니다. 위에서부터 채웁니다.

### ① 작업 폴더

「폴더 선택」을 눌러 3절에서 정한 폴더를 고릅니다.

### ② 받아 둘 저장소

받아 둔 저장소는 ✓ 로 보입니다. resource_common, sparkon_common, sparkon_cli 와 호 저장소 하나 이상이 ✓ 이면 할 일이 없습니다.

- ✕ 인 저장소는 옆의 「명령 복사」를 눌러 PowerShell 에 붙여 넣고 실행한 뒤 「다시 확인」을 누릅니다. 명령에 작업 폴더가 들어 있어 어느 폴더에서 실행해도 됩니다.
- 처음 받을 때 로그인 창이 뜨면 git.example.com 계정으로 로그인합니다.
- 폴더가 있는데 ✕ 이면 옆에 나온 글대로 합니다. 받다가 끊긴 저장소는 폴더 이름을 바꾼 뒤 다시 받습니다.
- resource_common 은 안에 common, font, landing 폴더가 있어야 ✓ 가 됩니다.
- 받아 둔 호의 완성본을 새 학습코드의 원본으로 씁니다. 용량이 되면 호 저장소를 모두 받아 두는 것이 좋습니다.
- **호 저장소는 「설정 완료」를 누르기 전에 받습니다.** 초기 설정을 마친 뒤에 받은 호는 앱이 내 브랜치를 만들어 주지 않아 main 브랜치에 남습니다. 그대로 「양산 완료 커밋」을 누르면 main 으로 올라갑니다. 나중에 호를 더 받아야 하면 먼저 담당자에게 묻습니다.

### ③ 자동으로 만드는 폴더

앱이 작업 폴더 안에 두 폴더를 만듭니다. 할 일은 없습니다.

- `SparkOn-양산기` 는 양산기 자료와 업데이트를 받는 폴더입니다.
- `SparkOn-리소스` 는 학습코드별 그림, 소리, 영상을 넣는 폴더입니다.

### ④ 사용자 정보

이름, 팀, 브랜치를 적습니다. 셋 다 적어야 합니다.

- 이름과 팀은 「검수 완료」를 누를 때 기록됩니다. 예: `seokho.yu(유석호)`, `my-team`
- 브랜치는 내 작업을 올릴 브랜치 이름입니다. 영문, 숫자, 마침표, 밑줄, 붙임표로 40자 안에 적습니다. main, master, head 는 쓸 수 없습니다. 예: `seokho.yu`
- 이 브랜치 하나로 sparkon_common 과 받아 둔 호 저장소를 모두 바꿉니다. 이미 쓰던 내 브랜치가 있으면 그 이름을 적습니다.
- 칸이 비어 있을 때 Tab 을 누르면 제안한 값으로 채웁니다. 이름과 브랜치 제안은 git 이름에서 옵니다. git 이름이 아직 없으면 ⑤에서 「저장」한 뒤에 제안이 생깁니다.
- 원격에 같은 이름의 브랜치가 이미 있으면 마지막 커밋의 작성자와 날짜가 보입니다. 내 브랜치가 맞으면 「이 브랜치를 따라갑니다」를 두 번 누릅니다. 남의 브랜치라면 다른 이름을 적습니다.

### ⑤ 필요한 프로그램

1절에서 설치한 프로그램이 ✓ 인지 봅니다. 필수가 모두 ✓ 여야 「설정 완료」를 누를 수 있습니다.

- ✕ 인 프로그램은 설치한 뒤 「다시 확인」을 누릅니다. 「설치 페이지 열기」는 설치 페이지를 브라우저로 엽니다.
- 「git 사용자」가 ✕ 이면 그 줄의 칸에 git 이름과 메일을 적고 「저장」을 누릅니다. 커밋에 이 이름이 적힙니다.
- Claude Code 가 로그인되어 있지 않다고 나오면 PowerShell 에서 `claude` 를 실행해 로그인한 뒤 「다시 확인」을 누릅니다.
- 로그인 상태를 확인하지 못했다고 나오면, 로그인했을 때만 「확인했습니다」를 누릅니다.
- poppler 는 없어도 됩니다.

### ⑥ 「설정 완료」

누르면 앱이 양산기를 받고 받아 둔 저장소를 준비합니다. 이미 된 것은 건너뜁니다.

- sparkon_common 과 호 저장소는 ④에 적은 브랜치로 바꿉니다. 그 브랜치가 없으면 origin/main 에서 새로 만듭니다. 푸시는 하지 않습니다.
- 패키지가 없는 호에만 패키지를 설치하고, 연결이 없는 호에만 공용 코드와 공용 리소스를 연결합니다.
- resource_common 과 sparkon_cli 는 브랜치를 바꾸지 않습니다.
- 끝나면 미리보기는 M 번호가 가장 큰 호에 연결되어 있습니다. 다른 호를 볼 때는 작업대의 「9호(M08)로 연결」 같은 단추를 누릅니다.
- 로그인 창이 뜨면 git.example.com 계정으로 로그인합니다.
- 패키지를 설치하는 호는 몇 분씩 걸립니다. 저장소마다 지금 하는 일이 한 줄씩 보입니다.
- 도는 중에는 앱을 끄지 않습니다. 끄려 하면 앱이 「하던 일이 있습니다」라고 먼저 묻습니다. 끄면 받기와 패키지 설치가 중간에 끊깁니다.
- 「설정 완료」가 끝난 뒤 「마치기」 전에 앱을 껐다면, 다시 켤 때 「초기 설정」이 다시 뜹니다. 같은 폴더를 고르고 「설정 완료」를 다시 누르면 이미 된 것은 건너뜁니다.

끝나면 저장소마다 ✓, !, ✕ 가 보입니다.

- ✕ 가 있으면 ✕ 옆 글대로 고친 뒤 「다시 실행」을 누릅니다.
- 저장소가 main 브랜치에 남으면 ✕ 이고 마칠 수 없습니다. main 에 남은 채로 마치면 「양산 완료 커밋」이 main 으로 올라가기 때문입니다.
  - 원격 브랜치를 따라가지 않아 남았으면 「이 브랜치를 따라갑니다」를 누르거나 다른 이름을 적은 뒤 다시 실행합니다.
  - 커밋하지 않은 변경이 있어 남았으면 그 변경을 커밋하거나 치운 뒤 다시 실행합니다.
- ! 는 확인만 하고 그대로 마칠 수 있습니다.

### ⑦ 「마치기」

✕ 가 없으면 「마치기」를 누릅니다. 설정을 저장하고 잠시 뒤 진행판이 열립니다.

## 5. 둘러보기

진행판이 처음 열리면 둘러보기가 한 번 저절로 시작합니다.

- 진행판, 작업대, 대화, 검수, 커밋, main 에 올리기를 차례로 짚습니다.
- 둘러보는 동안 이 창에서는 아무것도 만들거나 올리지 않습니다.
- 받을 리소스 창과 미리보기 창이 열려 있으면 닫고 봅니다.
- → 나 Enter 또는 「다음」으로 넘기고, ← 또는 「이전」으로 돌아가고, Esc 또는 「그만 보기」로 끝냅니다. 마지막 단계에서는 「마치기」를 누릅니다.
- 다시 보려면 앱 왼쪽 목록의 「둘러보기」 단추를 누릅니다.

## 6. 그다음

- 학습코드를 누르면 작업대가 열립니다. 리소스와 figma 화면을 넣고 「대화로 생성」을 누릅니다.
- 미리보기로 확인합니다. 「미리보기에서 확인할 것」이 보이면 확인한 뒤 「확인했습니다」를 누릅니다.
- 그다음 「검수 완료」, 「양산 완료 커밋」을 차례로 누릅니다. 「양산 완료 커밋」은 내 브랜치에만 올립니다.
- main 에는 진행판 맨 위의 「main 에 모두 올리기」로 올립니다. 올릴 목록을 먼저 보여 주고, 「이대로 올리기」를 한 번 더 눌러야 올립니다.
- 앱 왼쪽 목록 맨 위의 「업데이트」가 켜지면 누릅니다. 앱 새 버전을 받았으면 앱이 스스로 다시 켜집니다.
- 「업데이트」는 공용 저장소(sparkon_common)도 같이 받습니다. 공용 저장소가 작업 폴더 밖에 있으면 「설정」의 「공용 폴더」에서 위치를 바꿉니다.
- 대화, 「main 에 모두 올리기」, 모듈 회귀 검사가 도는 중이면 자료를 받지 않고 앱도 다시 켜지지 않습니다. 하던 일이 끝나면 「업데이트」를 다시 누르고 앱을 직접 다시 켭니다.
- 왼쪽 목록에 「새 모듈 n」이 보이면 스펙이 없는 모듈이 있다는 뜻입니다. electron-app 저장소에 푸시할 수 있으면 「요청문 복사」를 눌러 SparkOn-양산기 폴더에서 연 Claude Code 에 붙여 넣습니다.
- 푸시 권한이 없으면 누가 스펙을 올릴 때까지 기다립니다. 올라오면 「업데이트」가 켜집니다.

## 막히면

- 실행 파일이 안 켜지면 「실행이 막히면.txt」를 봅니다.
- 「초기 설정」의 ✕ 옆에 나온 글이 할 일입니다. 그대로 따라 한 뒤 「다시 확인」이나 「다시 실행」을 누릅니다.
- 그래도 안 되면 화면을 캡처해 담당자에게 보냅니다.
